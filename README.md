# luxuria-vr-app

صفحة «جولة VR» الخاصة بـ Emad Luxuria (`index.html`، نسخة 6): جولة ثلاثية الأبعاد بـ three.js r128 تعمل في المتصفح وعلى نظارة Quest (WebXR: VR وواقع مختلط)، مع ترتيب الأثاث بالذكاء الاصطناعي، ورفع مخطط الشقة، وجلسة مشتركة بين المصمم والعميل، وبطاقات ورشة، وتصدير «متطلبات التصميم».

> المشروع الرئيسي «توأم الغرفة» في مستودع `emad-al-deen-hq` (صفحة `vr/room.html`). لم يُحسم بعد هل هذه الصفحة ما زالت مستخدمة أم سبقتها تلك.

## المحتوى
| المسار | المحتوى |
|---|---|
| `index.html` | التطبيق كله في ملف واحد (~3000 سطر) |
| `glbdata/<SKU>.json` | 178 موديل أثاث (`EMAD-FURN-xxxx`)، كل ملف `{"sku", "b64"}` فيه GLB مرمّز base64 (~97 MB إجمالًا) |
| `brand/eg_logo_gold.png` | الشعار |
| `main.py` | ⚠️ **نسخة قديمة من البوابة لا تعمل هنا**: تستورد `hub.py` غير الموجود، وينقصها `/ai/plan`. البوابة الحالية في `emadluxuria/luxuria-vr-backend` |

## التشغيل
الصفحة تحمّل الموديلات بـ `fetch`، فافتحها عبر خادم ملفات ثابت وليس بفتح الملف مباشرة:
```bash
python3 -m http.server 8080
# ثم افتح http://localhost:8080
```
على النظارة: انشرها على استضافة HTTPS (WebXR يحتاج HTTPS) وافتحها من متصفح Quest.

## الربط بالبوابة
ميزات الذكاء الاصطناعي والجلسة تحتاج بوابة `luxuria-vr-backend`:
- **المصمم:** `index.html?gw=https://رابط-البوابة&key=مفتاح-المنظمة` (يُحفظان في المتصفح بعد أول مرة).
- **العميل:** الصفحة تولّد له رابطًا فيه `role=client&gw=…&room=…&ct=…`؛ فيه رمز العميل فقط، لا مفتاح المنظمة.
- بدون بوابة تعمل الجولة نفسها، وتتعطل ميزات الذكاء الاصطناعي والجلسة المشتركة.

لازم يكون نطاق الصفحة ضمن `ALLOWED_ORIGINS` في البوابة.

## حدود معروفة
- مجلد `voice/` (الذي تطلب منه الصفحة `voice/data/manifest.json` لنموذج صوت محلي) غير موجود في المستودع، فهذه الميزة لن تعمل.
- الموديلات بصيغة base64 داخل JSON أكبر بنحو الثلث من GLB الأصلي وتضخّم تاريخ git.
- مفتاح المنظمة للمصمم يمر في الرابط ويُحفظ في `localStorage`؛ لا تشارك رابط المصمم.
- لا توجد اختبارات آلية.
